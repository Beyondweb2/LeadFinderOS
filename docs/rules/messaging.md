**WhatsApp, SMS, Inbox** (`docs/twilio-comms.md`, `docs/whatsapp-templates.md`)
- Compliance is reviewed and NON-BLOCKING (`docs/whatsapp-outreach-compliance.md`): build no consent fields/blocking rules; never write that cold WhatsApp is definitively lawful or unlawful; opt-out/suppression stays as strict as it is. ⛔ An explicit opt-out blocks every MARKETING send, paying clients included (`recordOptOut()`).
- One sendable list `WHATSAPP_TEMPLATES`; a template lives in eleven places (parity tests fence them); names match Meta exactly. One initial opener at a time (`openerSendability`). Cold vs continuation (`coldOutreach.ts`); every cold-opener door asks `opener_contact_block`; queue eligibility is `coldWhatsAppEligibility.ts`. Only a logged CONVERSATION stops the cold opener. A pending Meta template gets a `*_APPROVED` constant and the gate goes FIRST — never "try it". Template params: no newline/tab/4+ spaces, ≤1024 chars (`forMeta()`). `dry_run` before a first real send; `test_send` costs a real message. Send window binds the QUEUE only. ⛔ Window open → an Inbox template goes as FREE TEXT, still recorded as that template (`inWindowFreeText.ts`, `docs/in-window-free-text.md`).
- ⛔ **Markets:** cold WhatsApp is UK mobiles by default (`ukColdDestination.ts`; India is no longer outreach). Malaysia/Singapore only through the per-country switch, after a handful tested by hand; failures start a 24-hour cool-down that restarts itself with a probe — never switch one on from code or loosen the rule. ⛔ **Every cold send, from the queue or a person, asks ONE rule** (`whatsappColdGuard.ts`, `docs/whatsapp-safety-guard.md`): each country's OWN cap (UK and Malaysia separate, no team cap), gap, probe, cool-down, tripwire. Australia is a WhatsApp-ONLY market and PROSPECT-ONLY (no price/guarantee/sign-up link; towns are `Name STATE`; hours from the lead's state zone). Market = `outreachMarkets.ts` / SQL `mobile_market`, from the digits, never `country`; a number's own code (+44/+60/+65/+61 or those digits bare) wins over the label (`waNumber.ts`, SQL `phone_market_country`), no code is never guessed. Refusal words come from `phoneCountry.ts` — never "UK only" (`docs/country-refusals.md`). Every non-cold send asks `whatsAppDestination.ts` (landline protected where it SENDS). `docs/my-sg-support.md`, `docs/australia-*.md`, `docs/india-readiness.md` (history).
- A failed send keeps Meta's own error (`sendErrorMeaning.ts`, never invent a meaning). 🔴 **`whatsapp-status` must NOT be deployed** until the Findable switch (`docs/whatsapp-status-cutover-plan.md`, top box; Move37's secret is unavailable; live is v129, rollback copy outside the repo) — skip it in any closure redeploy. Meta signs with the app that OWNS the webhook, and v129 enforces whatever secret is set: the Findable secret is saved in the same step as moving the webhook, never before. WhatsApp number health (`whatsappNumberHealth.ts`): yellow / red warn and change no cap; a tier drop or flagged / restricted number stops all cold WhatsApp until a person clears it.
- ⛔ WhatsApp and SMS are ONE Inbox component (`ConversationInbox({ channel })`; differences declared in `SMS_ONLY_DIFFERENCES`; `inbox-channel-parity.test.ts`). SMS status is DERIVED from receipts (`smsStatus.ts`; 30003 = SMS Failed, never No SMS). A text reply behaves like a WhatsApp reply (audit only). A pitch follows an audit ONLY under "Audit and reply" on WhatsApp. Queue-for-text never texts a lead tried on WhatsApp. Every Inbox send keeps the lead's send hours (`inboxSendWindow.ts`; `inbox_scheduled_sends`).
- ⛔ **AI handles replies** (`docs/ai-handles-replies.md`): ⛔ every AI-written reply needs approval; Auto is retired (`modeMayAutoSend` is always false; `aiAutoSend.ts` stays dormant). ONE Inbox mode Manual / Draft for approval (`inboxReplyMode.ts`; write the mode, not the old flags). One draft row per inbound. Code picks the move, the model phrases it (`replyMove.ts`, `offerFactSheet.ts`, `replyPlaybook.ts`); the pitch waits for audit + website check (`draftEvidenceWait.ts`). Needs-you flags run whatever the switch says; a stop/angry reply opts out at once. Status follows the messages in the DATABASE (`lead_status_target`); Visible is a FLAG (`apply_lead_visible`, ChatGPT never counts). Sales copy uses `salesStyle.ts`; spoken scripts say "Gemini". "AI named others instead" templates only when named in ≤ a third (`namedShareRule.ts`).
