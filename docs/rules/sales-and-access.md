**Auth, tenancy, Sales** (`docs/multi-user.md`, read before touching auth/RLS/lead reads/any edge function a rep can reach)
- ⛔ `user_id` stays on every table; anon+authenticated hold full DML grants — **RLS is the only barrier**. Role comes from `user_roles` only (`my_role()`, `_shared/access.ts`, `roleRules.ts`), never from the body / metadata. A new edge function calls `requireAdmin` or resolves role + `leadAccess`/`canWorkLead` (list it in `role-rules.test.ts`). A new page is admin-only by default (`access.ts`). Browser writes to `outreach_leads`/`ai_audits`/`ai_audit_runs`/`ai_audit_queue` are admin-only (RESTRICTIVE); Sales writes go through SECURITY DEFINER functions (`lead_set_*`, `claim_lead`, `sales_*`) — a direct sales update is a SILENT 0-row success. A salesperson never reads `outreach_leads` — the `sales_leads` view and role-checked functions only. ADMIN + SALES share ONE Outreach and ONE Inbox (never a SalesOutreach/second CRM). Owner scope applied by the PAGE before the table (`outreachOwnerScope.ts`); cross-owner contact needs "Queue across team".
- ⛔ **Next Action is human-set only** (`next_action*` written by no add/claim/send/reply/audit/cron path); ONE Next Action display (`nextActionView.ts`, `NextActionPill`); `call_booked_at` mirrors a Meeting only inside `lead_set_follow_up`. ⛔ Sales state is DERIVED (`salesStateOf`), never stored; `outreach_leads.status` stays the WhatsApp pipeline. Logged outcomes act only via `leadOutcome.ts`/`outcomePlan`. No automatic write overwrites a deal (`STRONG_STATUSES`). No audit result ever changes a lead's status. One status pill per lead row; Interested = gold star, never a pill.
- ⛔ **Abuse/cost protection** (`docs/abuse-cost-protection.md`): every paid/data-heavy action a PERSON starts calls `guardAction`/`allStopRefusal` (swept by `abuse-cost-protection.test.ts`); thresholds only in `protection_settings`; Sales never sees a cost; no CSV export for Sales. A salesperson's bulk check is `sales-prospect-check` ONLY, never `bulk-jobs`. The onboarding checklist no longer blocks selling; salesperson paperwork is Paul's, outside the app.
- Every lead write calls `notifyLeadChanged`; every lead reader listens (`leadSync.ts`). Self-sourced prospects/handoff, paid-client setup stage `deliveryStage`, client missing-info box (`clientMissingInfo.ts`), paid client auto-intake (`clientIntake.ts`; payment starts ONE crawl via the auto-intake, never from the webhook) — `docs/self-sourced-handoff.md`, `docs/paid-client-automation.md`, `docs/pre-sales-certification/`.
- Campaigns are OWNED, PRIVATE, globally unique (`docs/campaigns.md`); a rep's lead goes only into their own campaign; ONE WhatsApp queue panel for both roles (never forked); Delete = `campaign_archive`. One lead = `assign_lead_with_brief`; moving a lead never moves its history. Both dashboards use `salesDash/ui.tsx`; admin numbers come from `admin-overview-load.ts` → `adminMetrics.ts`.
- Social profiles: ONE grade rule + ONE canonical pick (`_social_profiles_sync`); never write `facebook_url`/`instagram_url`/`linkedin_url` from code — `saveGraded`; LinkedIn is never scraped; paid Enrich is ADMIN-ONLY (`docs/social-profiles.md`). Agency check, Companies House age, content & trust checks, one website check per lead (`websiteCheck.ts`), ⛔ a JS shell or unread page is never judged, prospect crawl cap 60 pages (`prospectCrawl.ts`), exhaustive crawls for clients, a crawl starts at the homepage, a failed crawl never overwrites a good one, ⛔ every site read uses ONE honest crawler name (`siteReadIdentity.ts`, never an AI bot's or a browser's), "blocked" only from robots.txt (`verifiedSearchBlocked`), an unread homepage is "couldn't check" — never a finding or a draft line (`docs/website-check.md`, `docs/agency-detection.md`, `docs/companies-house-age.md`, `docs/exhaustive-crawl.md`). `lead_crawl_checks` is ONE row per lead.
