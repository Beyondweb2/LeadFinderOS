## 2. Discipline checklist

**Recon.** Read the actual files before editing; grep to verify any list you were handed. Before asserting what a function receives, read its **callers**; before asserting a column is empty, read its **writer**. Inspect existing code before redesigning; V1 is the behavioural reference for V2.

**Git.** `git fetch origin`; prove `origin/main == HEAD` before branching (print both with variables). Branch per task; work in a **worktree** when another session may be open. Commit with `-F <file>`; end with `Co-Authored-By: Claude <the model this session is actually running, as the harness names it> <noreply@anthropic.com>` (never copy an older trailer). Commit only this task's files; **never stage** `HANDOFF.md`, `ONBOARDING.md`, `HANDOVER_NEXT.md`, `RECON_*.md`, `INVENTORY_DEEP_CLEAN.md`, `SQL_FOR_PAUL_*.sql`, `scripts/_*.ts`; never `git add -A`. Before merging: fetch, bring `origin/main` in, rerun relevant tests; merge `--no-ff`; prove origin unmoved immediately before pushing (refused push → fetch, rebase, retest, merge again). Branches are kept. Do-not-merge branches: `edge-check-gate`, `findable-product-rename`, `short-signup-url`, `full-measure-dials`.
- ⛔ **Never edit a source file with a PowerShell `Get-Content`/`Set-Content` round-trip or `-replace`** (mojibake, silent no-op). Use the Edit tool or a Node script reading/writing UTF-8.
- ⛔ **Backslashes do not survive the Bash tool** (heredoc / `node -e`): write SQL / regex / any backslash text through the Write or Edit tool, then diff it against what you meant.
- ⛔ **Never put a backtick inside a template literal**, not even in a comment — tsc recovers, `npm run build` doesn't.
- Never force-remove a worktree with a `node_modules` junction (unlink first). Never kill processes by name; kill only PIDs you started. Unique ports and temp profiles per run.

**Checks (verification tiers).** While working: `npm run check:quick` (typecheck vs baseline + advisory eslint + edge static checks) and `npm run test:changed`. Before commit/push/deploy: quick check + changed tests + `npm run build`. **The full gate `npm run check` (~3½ min) ONLY for migrations/database, messaging sending, auth, tenancy/RLS, payments/pricing, secrets** — once, after the last edit; never re-run on an identical tree. Copy/CSS/docs-only: quick checks, then verify the deployed site. Typecheck baseline = **9 errors as a LIST** (`scripts/typecheck-baseline.txt`); do not fix them. `npm run typecheck` does not cover `supabase/functions`: `check-edge-syntax`, `check-edge-undefined`, `check-import-graph` do (`--reached-by <file>` prints the redeploy list; `--orphans`). Every `src/lib` file reachable from an edge function uses **relative imports with explicit `.ts`** (no `@/`). A red suite is a real finding unless the runner's ENVIRONMENT banner says the findable-site copy is behind. Tests for deleted code are deleted in the same commit; a new client-facing renderer goes in `client-copy-claims.test.ts`; a new operator screen in `OPERATOR_SCREENS`.

**Deploy.** Production deploys originate from `main` only. **Backend before frontend; SQL first, confirmed by read-back.** One session at a time applies migrations or touches V2 staging data; migrations are applied one at a time (never `supabase db push`), staging only unless told. ## 3. Traps — rules (incidents in `docs/traps.md`)

- **The deploy check:** fetch the live HTML → read the chunk name → fetch that chunk → assert a marker from YOUR change → retry once (~90 s lag; Cloudflare can sit 15+ min — prove where live IS by the previous deploy's marker). No cache-buster. A shared component / lazy route has its OWN chunk. For an edge function grep `/functions/<slug>/body`. Local-vs-live hash comparison is invalid.
- A 200 with the right strings can be the wrong document (assert on something only the target has + byte count). A negative can be your own check's fault — grep the source for your needle first; grep counts lie (word boundaries, import statements). Not seeing something isn't evidence it isn't there (anon key gets `200 []` from RLS). "Identical everywhere" is a tell. When a model "gets it wrong", check what it was SHOWN before rewriting what it was TOLD. A stale comment is a load-bearing bug. `TaskStop` can report success while the process runs on.
- **Constants:** a rate copied from a price list is a guess until a billed row agrees. Name the constant, never write a cap/price as a number in prose. A constant the sync check must parse is a named `const` (never the declaration pattern in a comment). A `const` read before declaration throws at load (TDZ — `findableOffer.ts` is the checkout). Costs are per question. Apify is a single point of failure with a monthly cap (prospecting stops at 85%, client work 95%, everything at 100%; raising it is Paul's manual action) — recompute % from used/cap.
- 🔴 **An absent value falling through as a real one** (16 recorded). Never branch on known states and let `else` carry the rest; assert the grade you WANT (`=== 'established'`). On a spending/sending path absent = "do not"; on a picker absent ≠ offer ungated.
- 🔴 **One rule written in N places** — extract a leaf and import it; write the test "is there only one of it".
- 🔴 **A guard keyed to today's instance expires silently** — test the PROPERTY, not the identifier. Ask whether the case a guard protects can REACH it; drive every arrival including null.
- 🔴 **N callers that read "does it exist?" then spend all spend** — the guard is one conditional WRITE only one caller can win (`startClaimFilter`); read-then-create is never idempotent.
- A correctness decision never reads a client cache racing its own fetch (the DB is the dedupe). A parent reload flipping page `loading` unmounts dialogs — refresh in place. A conditionally-shown question owns its answer's lifetime. Remembered state must belong to the data it was set on.
- 🔴 **Protected calls go through `invokeEdge`** (`src/lib/edgeInvoke.ts`): `supabase.functions.invoke` sends the ANON key when `getSession()` has no token. A failed load is an error state with retry, never an empty list. 🔴 **A 401 only for a token the auth service refused**; auth/API not answering = 503 `auth_unavailable` / `upstream_timeout` (`_shared/operator-auth.ts` `resolveOperator`); `edgeErrorMessage` maps bare `server_error`.
- 🔴 **A secondary step must never hold a settled run** (competitor cleaning capped by `RETRY_CLEAN_CAP`; an exhausted receipt RELEASES the run). Never lower `MAX_RUN_AGE_MS` (12 min). Cutting question count saves money, not time (parallel; wall clock is one Apify scrape).
- **Edge:** the service-role-bearer branch is DEAD since ~2026-08-11 — working callers: CRON_SECRET via `x-cron-secret`, or an operator's admin JWT (don't re-probe). `sb_secret_…` keys are for `apikey` only; legacy `service_role` JWT for `/rest/v1` (say WHICH key). Function logs: Management API `analytics/endpoints/logs.all` (retention < 1 min — otherwise write to `client_error_reports`). `send-whatsapp-message`: 200+`ok:false` = designed refusal; "non-2xx" = handler 4xx/500; "Failed to send a request" = crash outside the catch. supabase-js errors are plain objects (`.message`). `CREATE TABLE IF NOT EXISTS` on a different shape is a silent no-op; `.neq()` drops NULLs; UTC end-of-day formats as next day in BST.
- ⛔ **Never add a `generated … stored` column (or anything rewriting) to a large live table**; plain column + trigger + batched backfill; `set local lock_timeout`. Never read a small key out of `results` in bulk — use `results_summary` / `_crawl_check` / `_seo_grade` / `gemini_answered`; a policy's `auth.uid()` goes in `(select …)`. ⛔ A LIST never reads `lead_crawl_checks.result` — `result_slim` through `useLeadCrawls`; a screen that SHOWS the check reads the full row. A remembered Outreach list is refreshed by the count-checked "changed since" read only (`outreachDelta.ts`) — never accept a delta without the count check.
- ⛔ **The app's Sign out is GLOBAL** (ends every session on that account); end only a test session with `/auth/v1/logout?scope=local`. ⛔ ~10 DB connections for everyone — never `invalidateQueries` on an interval shorter than the query. `ai_audits` / `ai_audit_runs` are NOT realtime-published. RLS with no policies reads as `200 []` (check `pg_policies`). The screen never reads `contact_suppressions` (`leads_suppressed`). `findable-onboarding` silently drops answer keys not in its three lists.
